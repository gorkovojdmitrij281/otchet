# VERSIONING.md
Файл политики контроля версий для проекта "AgriSubsidy"

## 1. Формат версии
Используем семантическое версионирование: `MAJOR.MINOR.PATCH`
- MAJOR — несовместимые изменения API или большая переработка.
- MINOR — новые функции, обратная совместимость сохраняется.
- PATCH — исправления багов, документации, мелкие правки.

Примеры:
- `1.0.0` — первый стабильный релиз
- `1.1.0` — добавлена новая функциональность
- `1.1.1` — исправлен баг в модуле расчёта

## 2. Ветвление (рекомендуемая модель)
Используем простую модель Git-Flow-подобную:
- `main` — стабильно протестированная ветка, релизы.
- `develop` — интеграционная ветка, туда мёрджатся feature-ветки.
- `feature/<short-name>` — ветки для новых фич (ответвляются от `develop`).
- `hotfix/<short-name>` — быстрые исправления в `main` (ответвляются от `main`, затем мёрдж в `main` и `develop`).
- `release/<version>` — опционально: подготовка релиза (фикс багов, подготовка CHANGELOG), затем мёрдж в `main` и `develop`.
